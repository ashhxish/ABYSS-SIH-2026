# CASE-001 — synthetic demonstration dataset

> **Synthetic Demonstration Dataset** — generated by
> `intelligence/data/demo/generate_case_001.py`, deterministic, no randomness, no network access.
>
> This dataset does **not** describe any real vessel, voyage, spill or incident. Nothing in it
> asserts that any vessel caused an oil spill. ABYSS reports *candidate vessels whose recorded
> movement is compatible with a reconstructed origin and release window*.

## 1. Why this dataset exists

The forensic engine (Phases 3–10) must be tested against a scenario whose intent is known in
advance. CASE-001 is that scenario: it is built so that a correct pipeline produces a specific,
checkable ranking outcome, and so that several tempting shortcuts (nearest vessel, biggest AIS gap,
strongest behaviour anomaly) produce visibly wrong answers.

**The central trap:** the observed slick is **33.4 km from the release point**. The oil drifted, so
proximity to the slick is *not* proximity to the release location.

| Origin uncertainty region | ellipse 10 km × 6 km (semi-axes) at bearing 50°, ~188 km², centroid 18.3000 N / 71.9000 E |

How the slick was derived: the demo drift field is integrated **forward** for 16 h from the release
point, which places the slick downstream. This makes the scenario internally consistent — it is not
an accident of coordinates. The drift model is a simplified prototype (see
`docs/methodology.md`) and its coefficients are not calibrated scientific constants.

## 5. Intentionally inserted anomalies

**Behavioural fixtures (the forensic story the engine must weigh in context):**

| Vessel | Fixture | Why it is there |
|---|---|---|
| V001 | Slowdown from 11.5 kn to 1.5 kn, loitering **inside** the origin uncertainty region during the release window | the strong, compatible candidate: spatial + temporal + trajectory agree |
| V004 | Slow (2 kn) loiter **near the observed slick**, 4 h before observation, ~125 km from the origin during the window | tests that a nearby, anomalous vessel is not automatically promoted |
| V006 | Repeated 24 h manoeuvring loop, speeds alternating 8 kn / 3 kn, 90° course changes every 3 h, always ≥150 km away | tests that a behavioural anomaly alone cannot produce a high rank |
| V008 | 126 stationary records from a legitimate fishing-like working pattern, ~170 km away | tests that slow/looping behaviour is not suspicious by itself |
| V011 | 216 stationary records from legitimate mooring periods, never more than ~25 km from its working corner | same, for port operations |

**AIS transmission gaps (deliberately paired to isolate *physical feasibility*):**

| Vessel | Gap | Bridge distance | Implied speed | Verdict |
|---|---|---|---|---|
| V002 | `2026-03-13T12:00Z` → `16:00Z` (4 h), beginning inside the origin region | 83.0 km | **10.8 kn** | physically feasible → the gap is relevant, and still weak evidence |
| V003 | identical timing and starting point | 274.5 km | **35.6 kn** | physically impossible → the gap must contribute almost nothing |

Both gaps overlap the release window and span the origin region. The only difference is whether the
bridge can be explained by vessel movement — which is precisely the constraint the specification
places on gap analysis: *an AIS gap alone must never strongly increase suspicion*.

**Data-quality defects (targets for Phase 3 cleaning — 13 rows in total):**

| Category | Rows | Vessel | Detail |
|---|---|---|---|
| `duplicate_record` | 4 | V007 | exact duplicates (same MMSI, timestamp, position, SOG, COG) |
| `malformed_timestamp` | 2 | V008 | `2026-03-12T25:61:00Z` and `12/03/2026 08:00` |
| `invalid_coordinate` | 2 | V010, V012 | null-island `(0, 0)` and latitude `95.2` |
| `negative_speed` | 1 | V006 | `SOG = -3.0` |
| `impossible_speed_jump` | 1 | V006 | one record 60 km from the next one 5 minutes later (~720 km/h). Because it teleports out and back it creates **two** impossible consecutive steps, both attributable to that single row |
| `missing_optional_field` | 3 | V011 | `heading` and `navigationStatus` blank; row otherwise valid |

Cleaning must **report** every rejection with a reason and a count (`cleaningStatistics`) — never drop
rows silently. Every defect is inventoried in `case_001.json` → `injectedDefects`, each with a
`defectId`, an `expectedPhase3Action` and identifying values.

## 6. Regenerating and verifying

```bash
# regenerate in place (must reproduce the committed files byte for byte)
python3 intelligence/data/demo/generate_case_001.py

# write somewhere else and compare
diff -r /tmp/case_001 intelligence/data/demo/case_001

# full Phase 2 validation suite (35 tests: identity, fields, quality, scenario design, determinism)
python3 -m unittest discover -s intelligence/tests -v
```

The generator runs **40 design self-checks** and refuses to write output if the scenario does not have
the properties described above (for example, if the slick were not downstream of the release point,
or if V003's gap were traversable).

## 7. Synthetic identifiers

| Field | Convention | Note |
|---|---|---|
| `MMSI` | `9000000NN` | a clearly synthetic block; ABYSS makes no claim about MMSI allocation |
| `IMO` | `9990xxC` where `C` is the real IMO check digit | format-valid so validation logic is exercised; **not** asserted to correspond to any real vessel |
| `vesselName` | `DEMO ...` | self-labelling synthetic names |
| `vesselType` | numeric AIS ship-type codes (70 cargo, 80 tanker, 60 passenger, 30 fishing, 52 tug) | real code list, synthetic usage |
| `datasetLabel` | `Synthetic Demonstration Dataset` on **every** row | fulfils the labelling requirement |

## 8. What this dataset must never be used to claim

1. That any of these vessels released oil, or is suspected of doing so.
2. That the release point is known — it exists here only as a **test fixture** for grading the
   hindcast; the product reports an uncertainty region.
3. That the synthetic environmental field, windage coefficient or drift model is scientifically
   calibrated. They are prototype values chosen for internal consistency.
4. That an AIS gap, a slowdown or a course change is evidence of wrongdoing. All three have ordinary
   explanations, and the controls (V007–V011) exist to demonstrate that.
5. That real-world AIS coverage looks like this. Real extracts are incomplete, noisier and
   provider-specific; this file exists to exercise the pipeline deterministically.
